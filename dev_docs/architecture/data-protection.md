# 数据防护（反低成本逆向 / 反爬）

> 状态：设计约束 v0.1（2026-10-22）｜适用：所有公开页面与接口

## 0. 目标与边界

- **目标**：不让别人用"调一个 JSON 接口"这种近乎零成本的方式整库搬走数据。要搬，就得在限流之下爬几千个 HTML 页面并逐页解析，而且这个过程能被我们**发现**和**举证**。
- **边界**：要做 SEO，页面就必须让搜索引擎读到真实数据。所以**做不到也不追求"无法采集"**，追求的是"成本高、可发现、可举证"。
- **不做**：前端解密 JSON（密钥就在浏览器里，几分钟就能破解，还拖慢页面）、对搜索引擎和普通用户展示不同内容（cloaking，会被搜索引擎惩罚）、在公开数据里掺假（伤害用户和信誉）。

## 1. 架构约束（硬规则）

```
浏览器 ──HTML──▶ Astro 公开站（公开数据唯一出口）──内网 + 服务令牌──▶ FastAPI 公开数据接口（不对公网暴露）
   │                 │
   │                 └─ 交互写操作（提交 / 反馈 / 订阅 / 登录）：Astro 服务端端点
   │                    → Turnstile + 限流 → 转发后端
   │
   └─ 后台 SPA ──JSON（登录 + 角色鉴权）──▶ FastAPI 后台接口 /api/admin/*
```

1. **FastAPI 的公开数据接口只接受内网调用**：Astro 服务端调用时带 `INTERNAL_API_TOKEN`，后端校验，缺失或错误一律拒绝。反代只把 `/api/admin/*` 对外暴露给后台 SPA。
2. **公网不提供可枚举的数据读接口**：没有 `/api/offers`、`/api/models?page=` 这类返回 JSON 列表的公开端点。
3. **筛选、排序、分页都走 URL 参数 + 服务端渲染**（`?sort=price&page=2` → 返回 HTML），不走客户端 fetch JSON。
4. **数据不随交互岛下发**。Astro 页面默认不带 JS 和数据；只有标了 `client:*` 的组件会把**它自己的 props** 序列化进 HTML。所以：
   - 列表、表格、详情页面一律服务端渲染（不加 `client:*`）
   - 交互岛（筛选面板、复制按钮等）只接收展示所需的最少字段，**禁止把整份数据集或原始记录作为 props 传下去**
   - 用 lint 规则加代码审查检查：带 `client:*` 的组件，props 类型禁止出现 `Offer[]`、`Deal[]` 等实体数组
5. **图表在服务端渲染成 SVG**（价格历史等）：浏览器拿到的是路径，不是数据数组；需要悬停提示时只放降采样后的少量点。
6. **搜索联想**最多返回 8 条 HTML 片段，带限流，不返回完整记录。
7. **管理后台接口**可以返回 JSON，但必须登录加角色鉴权，路径不出现在公开页面和 sitemap 中。

## 2. 对外数据出口的口径

| 出口 | 允许的内容 | 不允许 |
| --- | --- | --- |
| 公开页面 HTML | 完整展示数据（SEO 需要） | 隐藏字段、内部 ID、原始采集载荷 |
| JSON-LD | 当前页的单个实体或前 N 条（搜索引擎富结果需要） | 全量列表 |
| RSS | 最近 N 条：标题 + 链接 + 一句摘要 | 结构化价格或额度字段 |
| 可嵌入组件 | iframe 或图片卡片（服务端渲染） | 免费 JSON 接口 |
| sitemap | URL + lastmod | 数据字段 |
| **付费数据 API** | 结构化 JSON（**唯一的 JSON 出口**） | 无 Key 访问；带 Key 也要按额度限流 |

## 3. 流量层防护

- **Cloudflare 放在源站前**（不备案也能用）：WAF、Bot Fight Mode、按路径设限流规则；源站只放行 Cloudflare 的 IP 段。
- **应用层限流**（Astro middleware + Redis）：按 IP / IP 段 / UA 指纹分级。
  - 正常浏览：宽松
  - 短时间大量翻页或遍历大量详情页：先弹 Turnstile，再限速，最后封禁
  - 写操作（提交 / 反馈 / 订阅）：必须过 Turnstile
- **搜索引擎白名单**：Googlebot / Bingbot 通过反查 DNS 核验后放行，不受遍历限流；冒充搜索引擎 UA 的直接拦截。
- **robots.txt 策略**：允许主流搜索引擎；AI 爬虫是否放行单独决定（见第 6 节待决）。

## 4. 发现与举证

- **蜜罐链接**：页面里放对用户不可见、`robots.txt` 禁止访问、`nofollow` 的陷阱路径。访问它的必然是无视 robots 的爬虫，记录后封禁。不对搜索引擎展示不同正文，不构成 cloaking。
- **遍历检测**：统计单个 IP 或指纹在时间窗口内覆盖的详情页比例，超过阈值就告警。
- **出处与授权**：页脚写明数据版权和数据授权（单独的 `DATA_LICENSE.md`：允许署名引用，禁止批量搬运），出了问题有据可依。
- **可追溯标记**：每条数据带"最近确认时间"和出处链接；我们自己采集的时间戳精度和格式具有一致特征，可用于比对抄袭站（不篡改真实数据）。

## 5. 对其他设计的影响

- `roadmap.md`：RSS 只含摘要；可嵌入组件改为 iframe 或图片；数据 API 只做付费版。
- P0 骨架要包含：公开数据接口的内网令牌校验、Astro 限流 middleware、Turnstile 接入、交互岛 props 的 lint 约束。
- 前端交互体验：筛选和翻页靠服务端渲染，加 Astro 的预取（prefetch）和 View Transitions，体验接近 SPA，不需要客户端 JSON。

## 6. 关于二进制混淆载荷（参考 MindSet 的 `.bin` 方案）

MindSet 的做法是 deflate-raw 压缩后再与密钥流异或（`web-client/src/knowledge/codec-core.mjs`），密钥随前端代码一起下发。

- **作用**：挡住最低成本的那一层，即打开 DevTools Network 面板直接复制 JSON、通用爬虫自动识别 JSON 接口、让 LLM 几分钟写个脚本。
- **局限**：属于混淆而非加密。密钥和解码函数就在前端包里，懂行的人 10–30 分钟就能还原；用无头浏览器 hook `JSON.parse` 或直接读渲染后的 DOM，更是完全绕过。
- **在 52tokens 里的定位**：SSR 页面的 HTML 本身就含明文数据（SEO 需要），给这部分数据再套二进制没有意义。**只对不进 HTML 的客户端数据使用**，例如图表悬停用的数据点、对比工具的数据。主防线仍然是第 1 节："完整数据集不到客户端"。
- 如果采用：密钥每次构建轮换、解码函数随打包混淆；数据文件用短时效签名 URL 加限流，避免被直接枚举。

> 必须避免的坑（MindSet 现状里就有）：对搜索引擎 UA 下发预渲染明文 HTML，并且免于限流。这样任何人把 UA 改成 `Googlebot`，就能同时绕过混淆和限流。搜索引擎必须用反查 DNS（或 Cloudflare 的 verified bot 标识）核验真伪，核验通过前按普通访客处理。

## 7. 待决

1. **AI 爬虫（GPTBot、ClaudeBot、PerplexityBot 等）放行还是屏蔽**。放行可能带来 AI 搜索的引用流量，但数据会被它们吸收；屏蔽能保护数据，但损失这一流量渠道。建议：放行带引用的搜索型爬虫（如 OAI-SearchBot、PerplexityBot），屏蔽训练型爬虫（GPTBot、CCBot 等）。
